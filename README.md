# NetBox Server Wizard — серверы, сетевые карты, FC и проекты

Русскоязычный плагин для **NetBox 4.5.x**: регистрация нового физического сервера
в штатном разделе **Устройства**, расширение уже зарегистрированного сервера,
дополнительные Ethernet/FC адаптеры с серийными номерами, назначение проекта
и кабельная коммутация в одной форме.

> **Версия:** 0.3.0 — экспериментальная (MVP). Проверена структура исходников,
> синтаксис и сборка Python-пакета; полноценные интеграционные тесты на NetBox
> с PostgreSQL ещё не выполнены. Не устанавливайте сразу в продакшен.

## Сценарий работы

1. Откройте **Плагины → Добавить сервер / интерфейсы / кабели**.
2. Выберите площадку и один из режимов:
   - **Новый сервер** — заполните имя, модель, роль, стойку, серийный номер, статус.
     При сохранении появится полноценный объект `dcim.Device` в разделе **Устройства**.
     Порты из Device Type будут созданы штатной логикой NetBox.
   - **Существующий сервер** — выберите устройство. Мастер покажет его свободные
     физические интерфейсы. При необходимости можно добавить/исправить серийный
     номер корпуса (право `dcim.change_device`).
3. Выберите **Проект** или нажмите **+ Создать проект** и задайте название.
   Справочник проектов сохраняется в плагине; в NetBox 4.5 нет стандартной
   DCIM-сущности `Project`.
4. При необходимости нажмите **+ Добавить карту**. Для NIC или FC HBA укажите:
   - Наименование физической карты (например, `Intel X710` или `QLogic 2692`);
   - Серийный номер и артикул/модель (при наличии);
   - Тип `Ethernet` или `Fibre Channel` и физический тип портов;
   - От 1 до 8 имён портов через запятую (`ens2f0, ens2f1`, `fc0, fc1`).
5. На втором шаге выберите коммутатор и **свободный порт** для каждого
   интерфейса (включая порты из шаблона и добавленные на этом шаге).
   Для FC-порта будут показаны только FC-порты устройств выбранной площадки.
6. Нажмите **Сохранить сервер, карты, проект и кабели**.

Для каждого соединения создаётся стандартный объект `dcim.Cable` и связь
`dcim.Interface → dcim.Interface`. Кабели отображаются в штатном разделе
кабельного менеджмента NetBox.

**Всё сохраняется в одной транзакции PostgreSQL**: создание сервера,
интерфейсов, карт, назначения проекта и кабелей либо проходит целиком,
либо откатывается целиком. При сохранении занятость выбранных портов
проверяется повторно с блокировкой строк.

## Как хранятся данные

- Новый сервер: стандартный `dcim.Device`, серийный номер в `Device.serial`.
- Порты: стандартные `dcim.Interface`.
- Соединения: стандартные `dcim.Cable` (статус `planned` или `connected`).
- Проекты: плагиновая модель `Project`.
- Привязка устройства к проекту: `DeviceProject` (один основной проект на устройство).
- Дополнительная физическая сетевая карта / FC HBA и её серийный номер:
  плагиновая модель `Adapter`. Связи её портов с интерфейсами NetBox — `AdapterPort`.

На стандартной странице устройства NetBox появляется дополнительная панель
с проектом и инвентарными данными сетевых карт.

**Почему не `InventoryItem`?** В NetBox начиная с 4.3 `InventoryItem` устарел.
NetBox рекомендует `Module`/`ModuleType`, но для них требуются подготовленные
модели модулей и слоты `ModuleBay`. Эта версия плагина не создаёт фиктивные
слоты и не меняет существующие Device Type: карты хранятся в модели плагина,
порты — в NetBox Interface. Позднее можно добавить отдельный режим
учёта через штатные `Module`/`ModuleType`.

## Ограничения

- Одно основное проектное назначение на сервер.
- До 16 новых физических карт, до 8 портов на карту, до 64 физических портов
  на одну операцию.
- По умолчанию в выборе существующего сервера показываются все устройства
  площадки; целевые коммутаторы тоже не отфильтрованы по роли, пока не заданы
  параметры `server_role_slugs` и `switch_role_slugs`.
- Подключение поддерживается напрямую `Interface ↔ Interface`; патч-панели,
  breakouts, SFP, WWN, LACP, VLAN, IP адреса, PDU и автоматическая конфигурация
  коммутаторов пока не включены.
- Плагин не проверяет физическую совместимость трансиверов и кабеля.
  Он отличает только Ethernet от FC. Проверяйте конкретный тип среды и коннектора.
- Для отображения существующих устройств/стоек используется загрузка по площадке
  (до 1000 объектов); для больших площадок необходим поиск с пагинацией.
- Project/Adapter — модели Django в плагине. **Для них пока нет отдельного
  журнала изменений NetBox**; действия с устройствами/кабелями подчиняются
  штатной настройке журналирования NetBox.
- Текущий мастер не умеет удалить существующий проект, заменить карту,
  переименовать/удалить существующие порты или очистить серийный номер.
- Доступ к плагиновым справочникам определяется Django/NetBox permissions;
  перед открытием всем пользователям нужно проверить права на тестовом сервере.

## Установка и обновление с версии 0.2.0

1. **Сначала резервная копия** PostgreSQL и NetBox configuration.py.
2. Проверьте фактическую версию NetBox:

   ```bash
   /opt/netbox/venv/bin/python /opt/netbox/netbox/manage.py --version
   /opt/netbox/venv/bin/python --version
   ```

3. Установите из локального репозитория или из пакета:

   ```bash
   sudo /opt/netbox/venv/bin/python -m pip install --upgrade /opt/netbox-server-wizard
   ```

4. В `configuration.py` дополните существующие настройки, ничего не удаляя:

   ```python
   PLUGINS = [
       # другие установленные плагины
       "netbox_server_wizard",
   ]

   PLUGINS_CONFIG = {
       # другие настройки
       "netbox_server_wizard": {
           "server_role_slugs": ["server"],
           "switch_role_slugs": ["switch", "san-switch"],
       },
   }
   ```

   Значения `server`, `switch`, `san-switch` — **лишь примеры**.
   Впишите реальные `slug` ролей в вашем NetBox; иначе соответствующие
   списки окажутся пустыми. Если роль не нужно ограничивать, оставьте `[]`.

5. В версии 0.3.0 добавлены **четыре модели БД**, требуется миграция:

   ```bash
   cd /opt/netbox/netbox
   sudo /opt/netbox/venv/bin/python manage.py check
   sudo /opt/netbox/venv/bin/python manage.py migrate netbox_server_wizard
   sudo /opt/netbox/venv/bin/python manage.py collectstatic --no-input
   sudo systemctl restart netbox netbox-rq
   ```

6. Администратору (или роли) нужно разрешить как минимум просмотр
   `dcim.Device`, `dcim.Interface`, а для выполнения соответствующих операций:
   `dcim.add_device`, `dcim.change_device` (если меняем серийный номер),
   `dcim.add_interface`, `dcim.add_cable`, а также плагиновые права
   `view_project`, `add_project`, `add_deviceproject`, `change_deviceproject`,
   `view_adapter`, `add_adapter`, `add_adapterport` в приложении
   `netbox_server_wizard`. Для первой проверки используйте администратора.
   Настроенные ограничения на уровне объектов (`ObjectPermission`)
   требуют отдельных интеграционных тестов.

7. Откройте `/plugins/netbox_server_wizard/add/`.

Не забывайте закрепить пакет/версию в механизме обновления зависимостей NetBox,
например в `local_requirements.txt`.

### Проверка развёртывания

```bash
cd /opt/netbox/netbox
/opt/netbox/venv/bin/python manage.py check
/opt/netbox/venv/bin/python manage.py showmigrations netbox_server_wizard
/opt/netbox/venv/bin/python manage.py shell -c 'from netbox_server_wizard.models import Project; print(Project.objects.count())'
```

## Контрольные тесты перед продакшеном

1. Создать тестовый сервер с серийным номером; убедиться, что он появляется
   в разделе **Устройства** и создаёт интерфейсы из Device Type.
2. Создать проект прямо в мастере, затем выбрать его для другого сервера.
3. Добавить двухпортовую Ethernet карту и двухпортовую FC HBA, указать S/N.
4. Проверить, что в `dcim.Interface` появились все четыре порта, а в
   карточке сервера виден проект и серийные номера карт.
5. Подключить Ethernet порт к Ethernet коммутатору, FC порт — к FC коммутатору;
   убедиться в появлении кабелей в кабельном менеджменте.
6. Попробовать подключить к занятому порту или один порт дважды; проверить
   откат всей операции и отсутствие частично созданных устройств/карт.
7. Проверить два параллельных сохранения на один целевой порт.
8. Проверить пользователя с ограничениями ObjectPermission.
9. Проверить, что существующий сервер может получить новый проект и карту,
   без повторного создания устройства в `dcim.Device`.
10. Проверить имена/артикулы с кириллицей и пустые серийные номера.

## Разработка и быстрые тесты

```bash
python3 -m compileall -q netbox_server_wizard
python3 -m unittest discover -s tests -v
python3 -m pip wheel --no-deps --no-build-isolation -w dist .
```

Состав проекта:

```text
netbox_server_wizard/
  __init__.py
  models.py                 # Project, DeviceProject, Adapter, AdapterPort
  migrations/0001_initial.py
  forms.py
  views.py
  choices.py
  navigation.py
  template_content.py      # панель на карточке Device
  urls.py
  templates/netbox_server_wizard/
    add.html
    projects.html
    device_panel.html
pyproject.toml
README.md
tests/test_choices.py
```

Все тексты интерфейса и документации, за исключением технических названий
API/полей и принятых терминов Ethernet/FC, написаны на русском языке.
