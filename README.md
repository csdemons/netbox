# NetBox Server Wizard — мастер добавления серверов

Плагин для **NetBox**, позволяющий за один проход зарегистрировать физический сервер,
получить его сетевые интерфейсы из шаблона модели оборудования (*Device Type*),
выбрать коммутаторы и свободные порты, а затем сохранить сервер и кабельные
подключения в базе NetBox.

**Важное отличие:** плагин фиксирует схему коммутации в NetBox, но **не меняет
конфигурацию реальных коммутаторов**.

> **Статус проекта:** экспериментальная версия (MVP) `0.2.0`.
> Ориентир — NetBox 4.5.x и Python 3.12 или новее.
> Проверены синтаксис Python и сборка пакета. Интеграционные испытания
> на действующем NetBox пока не проводились. Перед продуктивной установкой
> протестируйте проект на отдельном экземпляре с резервной копией PostgreSQL.

## Как работает мастер

1. Откройте в меню **Плагины → Добавить сервер с подключениями**.
2. Укажите имя сервера, площадку, модель, роль, стойку, позицию, сторону стойки,
   серийный номер и статус.
3. Нажмите **«Показать интерфейсы и настроить подключения»**.
4. Мастер отобразит физические интерфейсы, предусмотренные шаблоном модели.
5. Напротив каждого интерфейса выберите коммутатор и один из его свободных портов.
   Строки без выбора подключения допускаются.
6. Нажмите **«Создать сервер и выбранные кабельные подключения»**.

Для каждого выбранного соединения создаётся объект `dcim.Cable`. Создание
сервера и всех кабелей выполняется в **одной транзакции PostgreSQL**:
при ошибке операция откатывается целиком.

### Что умеет версия 0.2.0

- Создавать физическое устройство с указанием площадки, роли, модели и размещения.
- Получать физические интерфейсы из `InterfaceTemplate` выбранной модели.
- Показывать коммутаторы той же площадки и запрашивать свободные порты по мере выбора.
- Исключать уже подключённые и помеченные как подключённые порты.
- Проверять, что один порт коммутатора не назначен сразу двум интерфейсам.
- Повторно проверять доступность целевых портов перед записью и блокировать выбранные строки БД на время операции.
- Выбирать статус кабеля — например, **запланирован** или **подключён**.
- Работать без новых моделей базы данных и без миграций плагина.

## Ограничения

- Мастер использует только интерфейсы из шаблона *Device Type*. Интерфейсы,
  добавляемые через модули или отдельные сетевые карты, пока не поддерживаются.
- Не более **64 физических интерфейсов** на устройство.
- По умолчанию в списке целевых устройств могут быть **все доступные устройства**
  выбранной площадки, не только коммутаторы. Для ограничения используйте
  настройку `switch_role_slugs`.
- Поддерживаются прямые подключения «интерфейс сервера → интерфейс коммутатора».
  Коммутация через патч-панели не предусмотрена.
- Плагин пока не настраивает VLAN, LACP, IP, MAC, SFP, iLO/iDRAC, PDU и другие параметры.
- Мастер расположен в меню плагинов, а не внутри стандартной формы создания устройства NetBox.
- Проверки прав NetBox выполняются по моделям и выборкам объектов.
  Дополнительные ограничения `ObjectPermission` для новых объектов необходимо
  отдельно проверить с действующей политикой доступа.
- Интерфейс и сообщения **самого плагина** написаны по-русски. Системные
  сообщения Django и стандартные варианты выбора NetBox зависят от локали NetBox.

## Проверка среды

На сервере NetBox (пути приведены для распространённой установки из исходников):

```bash
cd /opt/netbox/netbox
/opt/netbox/venv/bin/python manage.py --version
/opt/netbox/venv/bin/python --version
```

Убедитесь, что используемая версия NetBox совместима с `min_version = "4.5.0"`.

## Важно при обновлении прежней версии

В версии `0.2.0` изменены **Python-имя плагина, имя дистрибутива,
ключи `PLUGINS` / `PLUGINS_CONFIG` и URL**. Это несовместимое переименование.
Если предыдущая сборка уже установлена, удалите старый пакет из виртуального
окружения, замените запись о плагине и его настройках на
`netbox_server_wizard`, затем установите новую версию.
Не оставляйте старый и новый идентификаторы одновременно.

## Установка на тестовый экземпляр

**Не выполняйте установку сразу на продуктивном NetBox.**
Предварительно сохраните резервную копию базы и конфигурации.

Скопируйте каталог проекта на хост NetBox, например в
`/opt/netbox-server-wizard`, и установите пакет в его виртуальное окружение:

```bash
sudo /opt/netbox/venv/bin/python -m pip install /opt/netbox-server-wizard
```

В `/opt/netbox/netbox/netbox/configuration.py` добавьте плагин в **существующий**
список `PLUGINS`, не удаляя другие записи:

```python
PLUGINS = [
    # Сохраните здесь уже подключённые плагины
    "netbox_server_wizard",
]
```

При необходимости ограничьте выбор целевых устройств ролями коммутаторов:

```python
PLUGINS_CONFIG = {
    # Сохраните настройки остальных плагинов
    "netbox_server_wizard": {
        "switch_role_slugs": [
            "core-switch",
            "tor-switch",
            "management-switch",
        ],
    },
}
```

`core-switch`, `tor-switch`, `management-switch` — **примеры**. Укажите
реальные `slug` ролей из своего NetBox. Пустой список означает, что
ограничение по роли отсутствует.

Проверьте конфигурацию и перезапустите службы (их имена могут отличаться):

```bash
cd /opt/netbox/netbox
sudo /opt/netbox/venv/bin/python manage.py check
sudo /opt/netbox/venv/bin/python manage.py collectstatic --no-input
sudo systemctl restart netbox netbox-rq
```

Мастер появится в меню **Плагины → Добавить сервер с подключениями**.
Ожидаемый адрес страницы:

```text
/plugins/netbox_server_wizard/add/
```

Чтобы установка сохранилась при обновлении NetBox, зафиксируйте пакет
в `/opt/netbox/local_requirements.txt` или в другом принятом у вас
механизме управления зависимостями. Предпочтительно фиксировать версию.

## Права доступа

Для открытия мастера необходимы разрешения:

- `dcim.add_device`
- `dcim.add_cable`
- `dcim.view_device`
- `dcim.view_interface`

Для динамического списка стоек дополнительно проверяются `dcim.view_site`
и `dcim.view_rack`. Права на площадки, роли, типы устройств, стойки и
интерфейсы учитываются при формировании списков.

## План проверки перед запуском

1. Создайте тестовую модель с интерфейсами `eno1`, `eno2`, `ens1f0`, `ens1f1`.
2. Добавьте сервер со статусом кабелей «запланирован».
3. Проверьте, что занятые порты отсутствуют в доступных вариантах.
4. Попробуйте выбрать один и тот же порт дважды: операция должна завершиться ошибкой
   без появления нового сервера.
5. Проверьте конфликт при одновременном выборе одного порта двумя операторами.
6. Убедитесь, что сервер, интерфейсы и кабели сохранены корректно, а история
   изменений NetBox отражает операции согласно настройкам журнала.
7. Проверьте доступ пользователей с ограничениями `ObjectPermission`
   и входом через ваш SSO.
8. Проверьте ошибки размещения в занятой позиции стойки и модели высотой `0U`.
9. Сделайте и проверьте резервную копию PostgreSQL перед продуктивной установкой.

## Разработка

Структура пакета:

```text
netbox_server_wizard/
  __init__.py
  forms.py
  views.py
  urls.py
  navigation.py
  templates/netbox_server_wizard/add.html
pyproject.toml
README.md
```

Python-идентификаторы, имена модулей, настройки и URL оставлены без перевода
для совместимости с NetBox и Python. Тексты формы, кнопок, уведомлений,
описание плагина и документация — на русском языке.
